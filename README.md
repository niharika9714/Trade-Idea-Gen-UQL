# HKELI: metadata builder and chatbot API

This project has two capabilities:

1. Build and enrich `metadata.db` from a market database and document repository.
2. Run a FastAPI research chatbot using Ollama/Qwen, metadata discovery, original source retrieval and evidence citations.

Metadata describes where information is and what it means. Original database rows and document content provide answer evidence.

## 1. Install dependencies

Run the commands from the project root in PowerShell. Python 3.11 was used for validation. Install Ollama separately; pip does not install it.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements_complete.txt
```

Use the virtual environment's Python directly; activation is optional.

| Dependency | Purpose |
| --- | --- |
| `pydantic>=2,<3` | Typed models and validation |
| `fastapi>=0.110,<1`, `uvicorn>=0.28,<1` | HTTP API and server |
| `pypdf>=4` | PDF extraction |
| `python-docx>=1.1` | DOCX text and tables |
| `python-pptx>=0.6.23` | PowerPoint extraction |
| `Pillow>=10` | Image metadata |
| `extract-msg>=0.48` | Outlook MSG extraction |
| `pytest>=8,<10`, `httpx>=0.27,<1` | Regression and HTTP/testing utilities |
| `reportlab>=4` | PDF test fixtures |

SQLite is included in Python. `requirements_complete.txt` covers both capabilities. `requirements_agent_api.txt` alone omits document-parsing dependencies.

## 2. Configure source locations

Default data layout:

```text
data/
  metadata.db            # Created/updated by the builder
  market_data/
    market.db            # Existing source database; not generated by the builder
  documents/             # Original documents and referenced assets
```

Set variables before starting Python. This block points both capabilities at the same sources:

```powershell
$projectDir = (Get-Location).Path
$env:INVESTMENT_CHATBOT_DATA_DIR = Join-Path $projectDir 'data'
$env:INVESTMENT_CHATBOT_METADATA_DB = Join-Path $env:INVESTMENT_CHATBOT_DATA_DIR 'metadata.db'
$env:INVESTMENT_CHATBOT_MARKET_DB = Join-Path $env:INVESTMENT_CHATBOT_DATA_DIR 'market_data/market.db'
$env:INVESTMENT_CHATBOT_DOCUMENTS_DIR = Join-Path $env:INVESTMENT_CHATBOT_DATA_DIR 'documents'

$env:UQL_METADATA_DB = $env:INVESTMENT_CHATBOT_METADATA_DB
$env:UQL_MARKET_DB = $env:INVESTMENT_CHATBOT_MARKET_DB
$env:UQL_DOCUMENTS_DIR = $env:INVESTMENT_CHATBOT_DOCUMENTS_DIR
```

Replace paths as needed. Catalogued document `relative_path` values must resolve under the document root. Keep referenced document assets.

Variables apply to the current PowerShell terminal and child processes; configure them again in a new terminal. The project does not automatically load `.env` files. Builder settings in `app/config.py` are read at import time.

## 3. Build metadata.db

For deterministic enrichment without model calls:

```powershell
$env:INVESTMENT_CHATBOT_ENABLE_LLM = '0'
.\.venv\Scripts\python.exe -m scripts.build_metadata
```

Execution order:

1. Initialize the metadata schema.
2. Catalogue SQL tables, columns, relationships and value profiles.
3. Inventory document files.
4. Extract/enrich document summaries, terms, entities, sections and objects.

Supported inventory formats: PDF, PPTX, DOCX, PNG/JPG/JPEG and MSG. Image inventory does not interpret visual meaning; charts and attachments are not a complete visual/recursive extraction pipeline.

A missing market database causes SQL cataloguing to be skipped with a printed message. A missing document root yields no inventoried files. Check the reported source paths and counts.

Inspect the catalog:

```powershell
.\.venv\Scripts\python.exe -m scripts.show_catalog
.\.venv\Scripts\python.exe -m scripts.show_document_metadata --file D05 --limit 5 --terms 50
```

Rerun the builder after adding/changing files. Files marked `ENRICHED` are skipped until their size or modification time changes. The API does not automatically invoke or schedule metadata builds.

To re-enrich every registered document, for example after changing enrichment logic:

```powershell
.\.venv\Scripts\python.exe -c "from app.config import DOCUMENTS_DIR; from metadata.builders.enrichment import enrich; print(enrich(DOCUMENTS_DIR, force=True))"
```

This updates existing catalogued files; run the normal builder first to inventory new files. Back up an existing catalog before a full re-enrichment.

### Optional model enrichment

Ensure Ollama is running and the model is available, then set these before building or forcing re-enrichment:

```powershell
$env:INVESTMENT_CHATBOT_ENABLE_LLM = '1'
$env:INVESTMENT_CHATBOT_MODEL = 'qwen3:8b'
$env:INVESTMENT_CHATBOT_LLM_TIMEOUT = '180'
```

Model enrichment uses bounded extracted-text samples for summaries. It does not establish source facts or interpret images. Enabling it does not automatically reprocess unchanged `ENRICHED` files; use forced re-enrichment when needed.

### Builder environment variables

| Variable | Default | Meaning |
| --- | --- | --- |
| `INVESTMENT_CHATBOT_DATA_DIR` | `<project root>/data` | Default data directory |
| `INVESTMENT_CHATBOT_METADATA_DB` | `<data directory>/metadata.db` | Catalog output |
| `INVESTMENT_CHATBOT_MARKET_DB` | `<data directory>/market_data/market.db` | Source SQLite database |
| `INVESTMENT_CHATBOT_DOCUMENTS_DIR` | `<data directory>/documents` | Document root |
| `INVESTMENT_CHATBOT_ENABLE_LLM` | `0` | Exactly `1` enables model enrichment |
| `INVESTMENT_CHATBOT_MODEL` | `qwen3:8b` | Enrichment model; also used by the optional JEV helper |
| `INVESTMENT_CHATBOT_OLLAMA_URL` | `http://127.0.0.1:11434/api/chat` for enrichment | Full enrichment endpoint; see note below |
| `INVESTMENT_CHATBOT_LLM_TIMEOUT` | `180` | Enrichment timeout in seconds |

**URL convention:** enrichment expects a full `INVESTMENT_CHATBOT_OLLAMA_URL` endpoint. The optional API tool `get_jev_context` uses this same variable as a base URL and appends `/api/chat`. Leave it unset for normal local operation; each component has an appropriate local default. Custom overrides need component-specific handling because the current conventions differ. The main chatbot uses `UQL_OLLAMA_URL` instead.

## 4. Start Ollama and the chatbot API

If the model is not available yet:

```powershell
ollama pull qwen3:8b
ollama list
```

Ensure Ollama is running. If it is not already running through its desktop application or service, start it in a separate terminal:

```powershell
ollama serve
```

In the API terminal, run the source configuration in section 2, then:

```powershell
$env:UQL_MODEL = 'qwen3:8b'
$env:UQL_OLLAMA_URL = 'http://127.0.0.1:11434/api/chat'
$env:UQL_API_TOKEN = 'local-development-token'  # Example for local use; choose your own
$env:UQL_SYNTHETIC_ONLY = 'true'
$env:UQL_MAX_ROUNDS = '9'
$env:INVESTMENT_CHATBOT_MODEL = $env:UQL_MODEL

.\.venv\Scripts\python.exe -m uvicorn agent_api.server:app --host 127.0.0.1 --port 8000
```

The server occupies this terminal; Ctrl+C stops it. If port 8000 is occupied, stop its existing server or choose another port and update client URLs. Restart an existing server after changing code.

| Endpoint | Purpose |
| --- | --- |
| `GET http://127.0.0.1:8000/health` | API health |
| `http://127.0.0.1:8000/docs` | Interactive API documentation |
| `POST http://127.0.0.1:8000/v1/chat` | Research question |

### Chatbot environment variables

| Variable | Default | Meaning |
| --- | --- | --- |
| `UQL_METADATA_DB` | `data/metadata.db` | Existing metadata catalog |
| `UQL_MARKET_DB` | `data/market_data/market.db` | Source database |
| `UQL_DOCUMENTS_DIR` | `data/documents` | Original document root |
| `UQL_MODEL` | `qwen3:8b` | Main chatbot model |
| `UQL_OLLAMA_URL` | `http://127.0.0.1:11434/api/chat` | Full chat endpoint, including `/api/chat` |
| `UQL_API_TOKEN` | Unset | Required bearer token; unset means chat requests are rejected |
| `UQL_SYNTHETIC_ONLY` | `true` | Current API requires `true`; setting false rejects requests |
| `UQL_MAX_ROUNDS` | `7` | Execution-loop budget, clamped to 1-12; not a total model-call limit |
| `HKELI_DIAGNOSTICS_FILE` | Unset | Optional JSONL trace file containing prompts/results |

Relative API paths resolve from the working directory; absolute paths are preferable. Keep `INVESTMENT_CHATBOT_*` source settings consistent because reused helper modules import `app/config.py`.

For optional diagnostics, set this before starting the server:

```powershell
$env:HKELI_DIAGNOSTICS_FILE = Join-Path $projectDir 'logs/agent_diagnostics.jsonl'
```

To use a separate GPU Ollama host, point `UQL_OLLAMA_URL` at its full chat endpoint. The application has no separate GPU switch; GPU allocation is handled by the Ollama installation hosting the model.

## 5. Query the chatbot

In a second terminal, use the same token as the API server:

```powershell
$env:UQL_API_TOKEN = 'local-development-token'  # Must match the server
$headers = @{ Authorization = "Bearer $env:UQL_API_TOKEN" }
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/health'

$body = @{
    message = 'Retrieve the first five available D05 closing prices in January 2024. Return the source observations directly; no arithmetic is requested.'
} | ConvertTo-Json

Invoke-RestMethod -Uri 'http://127.0.0.1:8000/v1/chat' `
    -Method Post -Headers $headers -ContentType 'application/json' -Body $body |
    ConvertTo-Json -Depth 30
```

For document extraction, replace the message with:

```text
Read the original DOCX file D05_Investment_Committee_Note.docx for DBS Group (D05) and report NIM, ROE and CET1 from its Key Metrics table. Use document evidence, not SQL rows or catalog summaries.
```

Examples require the corresponding D05 data and document. Use questions suited to your actual catalog otherwise.

The request accepts `message` and optional `as_of`. January 2024 as an observation range does not require `as_of`. That field requests publication-time eligibility; arbitrary SQL and document inspection are not automatically certified for it, so such requests can be blocked.

Responses contain status, answer, citations, evidence, JEV/UQL planning, requirement coverage, execution trace and limitations. Inspect `status`: HTTP 200 can also contain a blocked, partial or clarification response.

## 6. Validation

Run the retained combined regression suite:

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests test_metadata_end_to_end.py test_binding_repair.py test_sqlite_binding_adapter.py test_binding_integration.py
```

If staged modules are archived, archive their matching tests and adjust the test selection. `FILE_CAPABILITY_MAP.md`, if retained, lists the dependency groups.

Run live checks with the API running and matching `UQL_API_TOKEN` set in the client terminal:

```powershell
.\.venv\Scripts\python.exe -m scripts.validate_live_chat --case sql --base-url http://127.0.0.1:8000
.\.venv\Scripts\python.exe -m scripts.validate_live_chat --case document --base-url http://127.0.0.1:8000
```

These checks require the supplied D05 dataset and DOCX file. Their source defaults are `data/market_data/market.db` and `data/documents`; use `--market-db` and `--documents-dir` for different locations. Results are saved under `test_results/`.

On 2026-10-12, the regression selection passed **181 tests, 1 skipped** (missing replay fixture). Actual FastAPI/Ollama SQL and DOCX checks passed against the original synthetic sources. These exact-query checks do not establish general routing quality, visual interpretation or production readiness. The current API is a synthetic-data prototype using bearer-token authentication.
